Workflow

核心操作流程

从产品说明书提取的完整实例运行路径

打开小程序 → 微信登录 → 创建/加入组织 → 上传课表 → 配置排班 → 生成结果
1

登录与身份选择 游客 / 微信登录

首次打开进入登录页，点击「微信一键登录」或「游客体验」先浏览功能。登录前需勾选同意《用户协议》与《隐私政策》。游客数据仅存本机。

2

创建或加入组织 管理员 / 成员

注册时二选一：「创建组织」（自动成为管理员）或「邀请码加入」（输入6位邀请码）。创建者获得邀请码并分享给成员。

3

上传课表 拍照 / 文件 / 手动

三种方式任选：拍照/截图上传（AI识别）、文件导入（Excel/CSV/PDF）、手动录入。识别不清的课程会标「?」供人工校正，识别为空会给出明确提示。

4

配置排班规则 管理员

设置值班日期、循环排班、排班周期、节次划分、班次设置（时间/人数）、排班规则（均衡/同日上限/间隔/连排）。配置保存后一键生成。

5

生成与查看排班 全体可见

系统以「班次×星期」课表式表格呈现结果，显示覆盖率统计。人手不足、超员或课表冲突会在「异常提示」中标红；管理员可点选单元格调整，支持导出分享。

6

成员管理 管理员

显示总成员/已传课表/未传课表统计。管理员可添加成员、代传/重新上传课表、删除成员、切换管理员身份；普通成员为只读视图。

3.2 三种识别策略

单遍网格转录法。让模型按"HEAD表头行 + R节次数据行"逐行读出，星期由表头文字确定、节次由行标签确定，避免"数格子"导致的列偏移。

# 模型输出示例
NAME:user
ID:20260801
HEAD:时间段|节次|星期一|星期二|星期三|星期四|星期五
R1-2:上午|1-2|·|·|高等数学|·|学术伦理规范与论文写作
R3-4:上午|3-4|·|管理学原理|·|·|·
R5-6:下午|5-6|Python语言|·|·|项目管理学|·
# 规则要点
# - 星期写中文
# - 空格用 · 表示
# - 识别不清的课程名末尾加 ? 标记

复用统一OUTPUT_FORMAT，输出"星期-节次:课程名"格式，程序直接解析为结构化数据。

# 文件识别输出示例
星期一-1-2: ·
星期一-3-4: 管理学原理
星期二-1-2: 高等数学
星期三-5-6: Python语言
# 格式：星期-节次: 课程名（空课程用 · 表示）

程序按表格坐标确定星期和节次，模型只负责清洗课程名，从根本上消除坐标偏移。

# Excel网格识别
# 程序逻辑：
# 1. 读取Excel单元格坐标 (row, col)
# 2. 表头行(col) → 映射到星期
# 3. 数据行(row) → 映射到节次
# 4. 模型只需清洗 cell.value 中的课程名
# 优势：坐标由程序确定，模型不参与定位，100%消除列偏移

3.3 关键工程决策 踩坑

从50秒超时到10秒响应 —— 一个Prompt格式的选择

❌ JSON格式输出

• 调用时长约 50秒

• 云函数60秒超时限制下频繁触发 ESOCKETTIMEDOUT

• 需容错解析非法JSON

• token量大，模型反复保证格式合法性

✅ 纯文本格式输出

• 响应仅需约 10秒

• 稳定快速，无超时风险

• 程序用确定性规则解析

• token更少，生成更快

排查过程：最初排查很久找不到超时原因，后来在网页端手动测试时发现，用自然语言询问让模型返回表格形式，响应仅需约10秒。分析原因：JSON输出token量大、模型需要反复保证格式合法性，而纯文本表格token更少、生成更快。最终将三个Prompt全部改为纯文本行输出。

Scheduling Engine

智能排班引擎

约束满足 + 贪心 + 回溯，生成均衡无冲突排班表

算法策略：约束满足 + 贪心 + 回溯

1 输入配置+成员课表 → 构建值班日期列表
2 过滤已上传成员 → 仅对有效成员进行排班
3 生成日期×班次Slot → 三重过滤候选人（课表冲突 / 空闲覆盖 / 手动屏蔽）
4 难排优先排序 → 可用人数越少的班次越先排
5 贪心分配 → 选择当前值班次数最少的成员
6 回溯腾位 → 若当前无法填满，回溯调整已分配人员
7 循环排班复刻 → 二次校验冲突 → 统计覆盖率 → 输出排班表+异常+统计

均衡机制（双维控制）

值班次数
统计每人被分配到多少个班次
值班时长
不同班次的时长权重不同（如周末班次权重更高）
人均上限
两个维度同时计数排序，人均岗位数上限做硬约束

避免"能者多劳"失衡，优于单纯轮转。系统优先分配给当前双维计数最低的成员。

异常处理

understaffed 人手不足 overstaffed 超员 conflict 课表冲突 rulebreak 违反规则

Design Decisions

设计决策复盘

6个关键决策，每个都是"问题 → 方案 → 效果"的完整闭环

1

API Key 不落前端

问题：小程序包可反编译，硬编码Key会泄露

方案：Key仅存云函数环境变量，前端间接调用

效果：源码零Key暴露

踩坑
2

纯文本输出而非 JSON

问题：JSON输出约50秒导致云函数超时

方案：改为纯文本行输出，程序确定性解析

效果：响应降至10秒，且无需容错非法JSON

3

网格转录对抗列偏移

问题：图片识别"数格子"容易星期列错位

方案：按表头文字和行标签"读文字"，Excel程序定位坐标

效果：根本消除偏移

4

空结果显式报错

问题：识别成功但0节课时静默返回空表

方案：统一0课程校验，返回EMPTY_RESULT

效果：杜绝静默丢数据

5

双维均衡排班

问题：单按次数轮转导致时长不均

方案：次数+时长双计数，人均上限硬约束

效果：岗位大致均分

6

游客数据本地隔离

问题：游客体验与数据上云需平衡

方案：游客数据仅本地，云端入口硬拦截

效果：机制保证不登录不上云
