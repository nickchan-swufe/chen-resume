      01 · 项目概述与需求背景

      产品定位
      「星轨成班」是一款以微信小程序为载体的值班自动排班工具，目标用户是高校学生会、社团等学生组织。组织管理员创建值班任务并录入排班规则后，成员各自上传课表，系统依据空闲时间自动生成排班表，替代传统的人工排班。

      要解决的痛点

          课表录入繁琐
          成员课表字段多、格式杂，逐条手工录入耗时且易错。系统支持拍照截图、Excel/CSV/PDF 导入，由大模型一次识别成结构化数据。

          人工排班易冲突
          人工核对空闲时间容易漏掉「上课时间重叠」或「连续值班」等问题。排班引擎以硬约束过滤候选，自动规避课表冲突。

          信息收集分散
          排班表散落在群聊、文件里，成员的课表还需管理员逐个催收汇总。系统用邀请码把成员拉进同一组织，成员自行上传课表、管理员免于逐一收集。

      从技术实现角度看，这个产品的核心难点不在表单交互，而在两处：如何让大模型稳定地把一张课表图片转成可靠的结构化数据（模型输出纯文本、程序判定解析），以及如何在满足约束的前提下生成一份均衡、可用的排班表。后文第 04、05 章重点展开这两块。

      02 · 需求目标
      产品目标分为「可用性」与「智能化」两条线，量化指标因尚未接入统计埋点，暂以占位符标注，待上线数据补齐后回填。

        3 步从「上传课表」到「生成排班」的操作步骤
        5 种课表导入格式（图片 / xls / xlsx / csv / pdf）
        20 个组织数据云函数接口（Action）
        —排班覆盖率 / 用户数（占位，待填充）

        降低排班耗时：把一次完整排班从人工的「数小时级」缩短到「分钟级」，以自动化的冲突检测替代人工逐条核对。
        降低录入门槛：成员无需理解数据结构，拍照或上传课表文件即可完成录入，识别结果支持人工修正。
        简化信息收集：管理员只需分享邀请码，成员各自上传课表，管理者不再逐人收集、核对、汇总课表。
        保证排班公平：通过值班次数、值班时长两个维度的均衡控制，让岗位在成员间大致均分，避免「能者多劳」失衡。
        尊重隐私与安全：游客模式下数据仅存本地、不上传云端；大模型 API Key 只保存在云函数环境变量，前端与源码均不接触。

      04 · 功能需求详解

      4.1 登录与游客模式
      小程序采用「先体验、后登录」的双态设计：用户打开小程序时不会被强制拉起授权弹窗，而是进入登录页，可自主选择「微信登录」或「游客体验」。
      登录态下，云函数 login 返回微信注入的 openid，作为组织成员身份的唯一标识；游客态则在本地写入 zhiban_guest_mode 标记，全局 isTourist 置为 true。游客可以浏览首页、查看排班演示等只读能力，但一旦点击「上传课表」或「文件导入」等需要数据上云的功能入口，会立即弹出登录引导（而非等到选完文件才拦截），从源头阻止游客把数据写入云端。
      数据隔离是这一模块的核心约束：游客产生的任何数据只写入本地存储，云层在 utils/cloud.js 的统一调用入口 call() 里加了一道硬校验——检测到游客身份时直接拒绝所有 orgdata 读写请求，不发起网络调用。

          角色可访问能力数据落点

            游客（未登录）浏览首页 / 排班演示 / 查看协议；不能上传或识别课表仅本地
            已登录成员上传课表、查看排班、加入/退出组织本地缓存 + 云端同步
            组织管理员管理成员、编辑任务/配置/排班、重命名/解散组织本地缓存 + 云端同步

      4.2 课表导入与 AI 识别
      课表导入是成员录入数据的唯一入口，也是产品价值的关键一步。成员在「上传」页选择拍照/截图、导入文件（xls / xlsx / csv / pdf）或手动录入，图片与文件先上传到云存储取得 cloud:// 形式的 fileID，再交由 kimivision 云函数识别。

      识别过程是「上传 → 云函数下载转 base64 → 调大模型 → 程序解析校验 → 返回课程表」的完整链路。大模型被要求输出逐行纯文本，而不是 JSON（见 5.3）：图片走单遍网格转录，让模型按「HEAD 表头行 + R节次 数据行」逐行读出课程，星期由表头文字、节次由行标签确定，避免「数格子」带来的列偏移；Excel 优先走确定性网格模式，星期/节次已有程序按表格坐标确定，模型只负责清洗课程名。
      模型返回的纯文本由云函数用确定性规则解析成 { days: {1..7: [{start, end, course}]}, studentName } 结构，附带不确定项（课程名以 ? 结尾）供人工校对。识别失败与空结果都有明确兜底：解析出 0 节课时返回 EMPTY_RESULT 错误并提示（而非静默给空表）；网格结构不符合预期时自动回退到列格式、逐行格式等旧解析路径。完整调用时序见第 05 章图 2、图 3。

      4.4 排班引擎与结果
      排班引擎是纯前端实现（utils/scheduler.js），输入为排班配置与成员课表/空闲时段，输出排班表、冲突异常与统计。引擎采用「约束满足 + 贪心 + 回溯」的组合策略。
      流程先构建值班日期列表，再按日期 × 班次生成待排的 Slot；对每个 Slot，用三重过滤计算候选人——课表时间是否重叠、空闲时段是否覆盖班次、是否被手动标记为不可排班。随后按「可用人数越少的 Slot 越先排」的难排优先顺序，用贪心法分配，并依据人均岗位数上限控制均衡。贪心填不满时触发回溯尝试腾位，仍不满则记入 anomalies 供复查。循环排班则以第一周结果为模板复刻到后续各周。

      Prompt 输出约定：逐行文本，而非 JSON
      三个 Prompt 都要求模型输出纯文本行，并用确定性规则解析。之所以不用 JSON，是因为文本输出 token 更少、生成更快，且前端/云函数无需容错地修补模型偶尔生成的非法 JSON。

          场景Prompt要求的输出格式

            图片课表PROMPT_VISION（单遍网格转录）NAME: / ID: / HEAD:列1|列2|… / R节次:格1|格2|…
            文件课表PROMPT_FILE（复用 OUTPUT_FORMAT）NAME: / ID: / 星期-节次:课程名
            Excel 网格PROMPT_GRID（模型只清洗课程名）星期-节次:课程名（星期/节次与输入严格一致）

          model: kimi-k2.6，stream: false（显式关闭流式，避免 SSE 解析异常）；
          max_tokens: 4096（密集课表 30+ 课程块时避免截断丢课）；
          temperature 保持在 0.2–0.3，换取更稳定的文本输出；
          云函数超时设为 60 秒，防止大模型长时推理触发 ESOCKETTIMEDOUT。

      5.5 错误码与边界

          错误码含义处理

            NO_API_KEY云函数未配置 Key引导配置 MOONSHOT_API_KEY
            API_ERRORKimi 调用失败展示「大模型调用失败」并保留原始信息
            EMPTY_RESULT解析到 0 节课提示更换清晰截图或改用文件导入
            PARSE_FAILAI 返回无法解析回退多格式解析，仍失败则报错
            TOO_MANY_IMAGES图片数量超限限制单次上传图片数

      06 · 数据模型
      云端数据划分为 5 个集合，采用「组织 → 值班任务 → 配置/排班」的嵌套模型：成员归属组织（跨任务共享），统计按任务拆分（taskStats）汇总，旧数据（配置/排班按 orgId 存储）在首次访问时自动迁移到「默认任务」。

          集合主键/文档关键字段

            organizations组织 idname, inviteCode, creatorOpenid, createdAt
            members成员 idorgId, openid, name, studentId, isAdmin, schedule, freeTimes, customBlocked, taskStats, dutyCount, dutyHours, scheduleUploaded
            tasks任务 idorgId, name, createdAt
            configstaskId 作为文档 idtaskId, orgId, config（dutyDays/loop/dateRange/periods/shifts/rules）
            schedulestaskId 作为文档 idtaskId, orgId, days（按日期的排班数组）

      前端同时维护一份本地缓存（utils/storage.js），登录/进入组织时从云端全量拉取，写操作先落本地、再同步云端（静默同步，失败不阻断、下次进入再兜底全量拉取）。游客态的数据只写本地，不触碰云端集合。

      07 · 关键设计决策

        API Key 不落前端
        Kimi 的访问凭证只存在云函数环境变量里，前端经 kimivision 云函数间接调用，源码与小程序包均不含 Key，杜绝随包泄露。

        逐行文本输出，而非 JSON
        三个 Prompt 都要求模型输出「姓名 / 学号 / 星期-节次:课程名」这样的纯文本行，由云函数用确定性规则解析成结构化 JSON。相比让模型直接吐 JSON，文本输出 token 更少、生成更快，也免去了对模型偶尔生成的非法 JSON 做容错修补。

        网格转录对抗「数格子」偏差
        课表图片最典型的识别错误是列偏移。网格模式让模型按表头文字与行标签「读文字」而非「数格子」，Excel 更进一步由程序按表格坐标定位星期/节次，模型只清洗课程名，从根上消除偏移。

        空结果必须显式报错
        识别「成功」但 0 节课（模型输出格式不被识别、课程行被丢弃）会静默丢数据。系统对图片与文件统一做 0 课程校验，命中即返回 EMPTY_RESULT，避免用户在无提示下看到空表。

        排班均衡的双维控制
        以「值班次数 + 值班时长」两个计数做贪心排序依据，并以人均岗位数上限做硬约束，使岗位在成员间大致均分，优于单纯按次数轮转。

        游客数据本地隔离
        游客身份在云端统一调用入口处被硬拦截，从机制上保证「不登录不上云」，而非依赖每个页面各自判断。

      本文档基于项目源码与云函数实际实现整理，未引用外部网络资料。涉及的数据指标（覆盖率、用户数、效率提升幅度）尚未接入统计埋点，以占位符标注，待上线数据补齐后回填。
